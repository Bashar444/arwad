# ADR-0006: PLS-SEM engine matched to seminr by black-box tests

- **Status:** Accepted
- **Date:** 2026-10-27

## Context

The third Phase 2 engine is the PLS-SEM path algorithm with its bootstrap, the method behind most PLS-SEM studies in management research and the first engine planned for the PalmyraDoor research portal. The reference implementation in R is `seminr` (Ray, Danks and Calero Valdez; GPL-3). Researchers report `seminr` results, so the engine has to give the same numbers, not merely close ones. `seminr` is GPL-3 and Arwad is MIT, so the clean-room rule of [ADR-0003](0003-mit-licence-dco-clean-room.md) applies to it as it does to GNU R.

## Decision

1. **Algorithm from the literature, rounding from black-box tests.** The kernel `aw_pls_kernel()` (in `r/R/engines.R`, written in the compilable subset) implements the PLS path algorithm as published (Wold, 1982; Lohmöller, 1989; Hair, Hult, Ringle and Sarstedt, *A Primer on PLS-SEM*, 4th ed.): Mode A outer weights, the path weighting inner scheme, standardised indicators, convergence on the sum of absolute weight changes. Where the literature leaves a numerical choice open, the choice was settled by comparing `seminr` 2.5.0's outputs with candidate formulas on many inputs, including `seminr`'s exported and internal functions called as black boxes on our own inputs:
   - indicators and scores are standardised as `scale()` does (mean by `colMeans()`, divisor `sqrt(sum(x^2)/(n - 1))`); each iteration standardises the scores and the inner proxies;
   - weights are normalised by the uncentred root mean square of their scores, `sqrt(sum(y^2)/(n - 1))` (300 of 300 random inputs identical);
   - the iteration count reported is the number of updates minus one; `maxIt` allows `maxIt + 1` updates;
   - loadings are `cov(Z, Y)` on the final, unrescaled scores; R² is `1 - 1 / solve(S)[k + 1, k + 1]` for the correlation matrix `S` of (antecedents, construct);
   - bootstrap resample `b` is `sample.int(n, replace = TRUE)` after `set.seed(seed + b)`, which is why `seminr`'s results do not depend on the number of cores; without a seed, `seminr` draws one with `sample.int(100000, 1)`;
   - HTMT uses absolute correlations.
2. **Three compiled builtins** were added for the kernel, each matched to GNU R by black-box tests: `colMeans()`, and `cov()` and `cor()` of two vectors (the corrected two-pass mean of Chan, Golub and LeVeque, 1983; extended-precision deviations and sums; a correlation's standard deviations are rounded from an extended-precision square root). On 64-bit ARM, R's own results depend on how its C compiler vectorises and fuses the summation loops (a CI diagnostic on macOS showed that no fixed C formula reproduces them reliably), so there the compiled `cov()` and `cor()` call the routine R itself calls, `.Call(stats:::C_cov, ...)`, and are R's by construction.
3. **Native, and checked to be native.** `aw_compile()` falls back to GNU R without an error when a function leaves the subset; the first draft of the kernel did (it assigned whole matrix columns), so the first benchmark timed interpreted R. The kernel now assigns elements, and the tests assert that the engine's unit is compiled and that no call bailed out (`aw_explain()`).
4. **Scope of the native path:** Mode A (composite or reflective), path weighting, complete numeric data, no interaction terms or higher-order constructs. Anything else is passed to `seminr::bootstrap_model()` itself, and the result says so (`native = FALSE`).
5. **What is claimed.** Bit-identical to `seminr`: outer weights, loadings, path coefficients, iteration count and final weight change of the estimate; the bootstrap arrays of path coefficients, total effects, loadings and weights and their descriptive tables. Not bit-identical: HTMT, which agrees to within four units in the last place (corrected 28 October 2026: first stated as two, from the 3-resample test runs; over 1,000 resamples the ECSI model has values 3 units apart and the Primer's extended corporate reputation model one value 4 units apart, largest relative difference 4.9e-16, about three in four values identical); the exact summation order `seminr` uses for it was not found by black-box search, and this is stated wherever the engine is described.

## Clean-room record

`seminr` stores its inner-weighting function in every fitted model, so printing a model object during the first probe displayed the body of `path_weighting()`; printing `seminr::mode_A` to see whether it was a constant displayed its one-line body. Both state textbook definitions (regression coefficients on antecedents and correlations with successors; Mode A weights as covariances with the inner proxy). No other `seminr` source was read; every other numerical detail above was established from outputs only. No `seminr` code is copied, translated or paraphrased in this repository.

## Consequences

- `aw_boot_pls(model, nboot, seed)` is a drop-in replacement for `seminr::bootstrap_model()` that returns a `boot_seminr_model` object, so `summary()` and `seminr`'s plots work on it.
- `seminr` becomes a suggested package; the tests compare against it on 54 models (8 on `seminr`'s own datasets, 46 seeded synthetic ones) on Linux, macOS and Windows.
- Mode B, the factorial and centroid schemes, PLSc, interaction terms and higher-order constructs are the next candidates for the native path.

## Amendment (28 October 2026): speed

Profiling by switching parts off showed half of each resample in correlations computed pair by pair for HTMT and in the cross-loadings (needed only for seminr's signed zeros), each call recomputing column means. The kernel now computes the loadings with one `cov(Z, Y)` and HTMT with one `cor(Xb, Xb)`, compiled matrix forms that compute each column's mean and standard deviation once: 5.15 to 2.85 ms per resample of the ECSI model, results unchanged. `aw_boot_pls(cores = )` runs blocks of resamples in separate processes (forked on Linux and macOS, a socket cluster on Windows) rather than threads, because on 64-bit ARM the compiled `cov()` and `cor()` call into R, which is not thread-safe; the resample indices are drawn before the split, so results do not depend on the number of cores. Headline speed ratios against seminr use its fastest run, because its time varied from 212 to 655 s for the same 10,000 resamples on the benchmark laptop.

## Amendment (28 October 2026, later): column statistics kept by the compiler

A second profile (each part of the kernel replaced by a stand-in, 11 fixed iterations against one) put 80% of a resample in the iterations: per iteration 0.11 ms in the Mode A covariances `cov(Z[, k], Yt[, j])`, 0.09 ms in the inner regressions and 0.07 ms in the inner correlations `cor(Y[, i], Y[, j])`. Each of those calls copied two columns and recomputed both means (and standard deviations), although the indicators `Z` do not change during the iterations. Rather than rewrite the kernel around this, the compiler now keeps, for every matrix whose columns a function passes to `cov()` or `cor()` as `m[, j]`, each column's mean and standard deviation with an epoch that every write to the matrix advances; the columns are read in place ([spec](../../spec/subset-v0.md)). The arithmetic is the same as before, so results are unchanged bit for bit (the 54-model comparison with `seminr` and a new test that writes to the matrices between calls). The kernel also builds each regression's transposed design once. 1,000 resamples of the ECSI model: 2.86 s before, 2.06 s after, on the benchmark laptop; the benchmark report has the full table.

## Amendment (28 October 2026, session 4): Mode B

Formative constructs, `composite(..., weights = mode_B)`, are now on the native path; the Primer's extended corporate reputation model, whose four driver constructs are formative, is the case that matters for management research. The literature defines Mode B weights as the coefficients of the inner proxy regressed on the construct's standardised indicators (Lohmöller, 1989; Hair et al., 2027). Ten numerical forms of that regression were compared with `seminr` 2.5.0's estimates on three models (`solve()` of the correlation, covariance or cross-product system; the explicit inverse times the right-hand side for each; `.lm.fit()`; `lm()` with and without an intercept). Exactly one reproduced `seminr`'s weights and path coefficients bit for bit on all three: `solve(cor(Zj)) %*% cor(Zj, proxy)`, the explicit inverse of the block's indicator correlations times their correlations with the proxy; the others differed by 2e-16 to 3e-15. The weights are then normalised to unit-variance scores as in Mode A, and loadings, HTMT, iterations and the bootstrap follow the Mode A rules unchanged (loadings and HTMT of a Mode B model checked against `seminr` directly). `seminr` rejects a Mode B construct with one indicator, so such a model never reaches the engine.

This needed a new compiled builtin, `cor(X)` (and `cov(X)`) of one matrix. Black-box tests showed that GNU R's `cor(X)` differs in the last bit from `cor(X, X)` in about two cases of three, while `cov(X)` equals `cov(X, X)`; the rule that matched 3,000 of 3,000 random matrices is the covariance matrix divided by the product of the double-precision square roots of its two diagonal entries, with the diagonal set to exactly 1 and the rest clamped to [−1, 1]. On 64-bit ARM the compiled code calls R's own routine with `y = NULL`, as it does for the two-argument forms. The inverse of each Mode B block's correlations does not change during the iterations of a resample, so the kernel computes it once per resample.

Clean room: `seminr::mode_B` was used only as an argument; its body was not printed or read. Result: estimates and bootstrap arrays bit-identical to `seminr` on all 26 Mode B models in the test set, and on 10,000 resamples of the Primer's extended model in the benchmark (HTMT within four units in the last place, as item 5 now states). Measuring that model's HTMT in units in the last place, rather than as a relative difference, is what showed that the earlier wording ("two units") was too tight.

## Amendment (28 October 2026, session 6): consistent PLS, and the resamples' settings

Models with `reflective()` constructs, which `seminr` estimates by consistent PLS (PLSc), are now on the native path. The literature defines the method (Dijkstra and Henseler, 2015): from a construct's final weights `w` and its indicators' covariance matrix `S`, `rho_A = (w'w)^2 * w'(S - diag S)w / w'(ww' - diag ww')w`; the consistent loadings are `w` times `sqrt(rho_A) / (w'w)`; the construct correlations are divided by `sqrt(rho_A,i * rho_A,j)`, and the path coefficients are least-squares coefficients on the corrected correlations. Black-box tests against `seminr` 2.5.0 settled the rest, on 154 probe models (the 80 test models, each with all constructs reflective and with every second one reflective, less six for which `seminr`'s own estimate already contains NaN, with the warning `NaNs produced`):

- Only loadings, path coefficients and R² change; weights, scores, iterations and the final weight change are those of Mode A. `seminr` marks reflective constructs with type `C` in the measurement matrix.
- `S` is the covariance matrix of the standardised indicators (`cov()` of `scale()`d data); the quadratic forms as written, with the diagonals set to zero; `rho_A = (w'w)^2 * (num / den)`; loadings `sqrt(rho_A) / (w'w) * w`. Bit-identical on 485 of 485 reflective blocks with two or more indicators (other forms tried: `cor()` of the raw or standardised data, cross-products, `cov2cor()`, and ten forms of the loading formula, among them `sqrt(num / den) * w`, which matched 347). A single-indicator reflective construct has `rho_A = 1` and the same loading formula (59 of 59).
- Paths: `solve(Rc[pred, pred], Rc[pred, j])` for each endogenous construct, where `Rc` is `cor()` of the final scores divided by `sqrt(outer(rho, rho))` with the diagonal set to 1 (154 of 154 models; the explicit inverse, `qr.solve()`, Cholesky and normal-equation forms matched 27 to 33). In a model with a reflective construct every path comes from `Rc`, also those among composites.
- **Which constructs are corrected.** `seminr` uses `rho_A` for every Mode A construct with two or more indicators, `composite()` ones included, and 1 for Mode B constructs and single indicators: this rule matched 154 of 154 models; correcting only reflective constructs matched 83, correcting Mode B ones too 139. The published method corrects constructs modelled as common factors and leaves composites as they are, so a model that mixes `reflective()` and `composite()` constructs gets corrected composites from `seminr`. Arwad keeps `seminr`'s rule, because `aw_boot_pls()` bootstraps the estimate `seminr` produced, and an estimate and its bootstrap must come from the same procedure; `?aw_boot_pls` states the rule.
- **Resamples where consistent PLS is undefined.** When a `rho_A` is negative (`seminr` then takes the square root of a negative number and warns), `bootstrap_model()` leaves the resample out, numbers the remaining slices 1 to k and sets `boots` to the number requested minus the failures (in the type it was given), with a message that calls them failures to converge. The kernel marks such a resample in a new status column, the wrapper leaves it out the same way and says so in its own message. With fewer than two resamples left (including `nboot = 1`), `seminr` stops: it reports an error and returns the model unbootstrapped, or, depending on the calling context, the error reaches the caller; `aw_boot_pls()` hands that case to `bootstrap_model()`, so the outcome is `seminr`'s.
- **The resamples' settings (a fix that concerns every model, found on this occasion).** `bootstrap_model()` estimates every resample with `seminr`'s defaults, `maxIt = 300` and `stopCriterion = 7`, whatever the model was estimated with (tested with models estimated at `maxIt` 2, 5 and 3,000 and `stopCriterion` 3 and 12). Until this change `aw_boot_pls()` used the model's own settings, which differs from `seminr` when a model was estimated with another `stopCriterion`, or when a resample needs more than 300 iterations under `maxIt = 3000` (the case that showed it: a 40-case synthetic model with one resample needing 588). The published comparisons and benchmarks met neither case. The original sample, used for HTMT and total effects in the descriptive tables, keeps the model's settings, as in `seminr`.

The kernel's mode 3 runs Mode A weights in the iterations and the correction after them; the correction needs only builtins that existed (`cov()` and `cor()` of one matrix, `t()`, `%*%`, `solve()`). A first version took the square root of a negative `rho_A` for the loadings of a resample that is left out anyway; R warns there, so the compiled code handed those calls back to GNU R (45 of 462 calls in the probe run: correct, but slow). The loadings of such a resample are no longer computed, and the probe run has 0 of 462 calls handed back. Result: estimates and 30-resample bootstraps bit-identical to `seminr` on all 154 probe models, HTMT within four units in the last place as before; the test set now has 125 models, 46 of them with reflective constructs.

Clean room: `seminr`'s consistent-PLS function was not printed or read. One test traceback printed the call in which an error arose inside `bootstrap_model()`'s condition handler: a test of the number of failed resamples and the text of the message above. It contains no numerical procedure. No `seminr` code is copied, translated or paraphrased here.

## Amendment (29 October 2026): seminr 2.6.0

`seminr` 2.6.0 reached CRAN on 13 October 2026 and changed consistent PLS. The CI installs the current CRAN release, this laptop still had 2.5.0, so the session-6 commit passed locally and failed on every CI system (218 failures, all in models with reflective constructs). The release's NEWS and help pages describe the changes; the numerical rules below were measured by black-box tests against 2.6.0, installed in a separate library so that the laptop's research library stays on 2.5.0.

**Decision.** `aw_boot_pls()` follows the installed version (`aw_seminr_260()`): its result must equal what `bootstrap_model()` returns on the same installation, and a model saved under 2.5.0 is bootstrapped by 2.6.0 under 2.6.0's rules. The CI checks both: one Linux job installs 2.5.0 from the CRAN archive.

- **Composites are no longer corrected.** 2.6.0 gives every composite `rho_A = 1`, as Dijkstra and Henseler (2015) do; path coefficients and R² of models that mix `reflective()` and Mode A `composite()` constructs change, loadings and all other models do not. The kernel keeps 2.5.0's rule as mode 4 (a Mode A composite with the `rho_A` correction and uncorrected loadings), which the spec assigns only under seminr < 2.6.0. Item "Which constructs are corrected" of the session-6 amendment describes 2.5.0.
- **Which resamples are dropped.** `bootstrap_model()` keeps exactly the resamples whose estimation neither fails nor warns, in their order: the kept sets agreed on 46 of 46 models with reflective constructs at 60 resamples each. A `rho_A` of zero or below makes `estimate_pls()` stop (105 resamples); the only warning that occurred is the one for inadmissible solutions (906 of 2,655 estimated resamples). With fewer than two resamples kept, `bootstrap_model()` reports an error and returns the model unbootstrapped, as before.
- **Inadmissible solutions.** The warning names every condition it found. Each condition was matched against candidates computed from `seminr`'s outputs, then its threshold measured by bisection: noise blended into a flagged resample until that condition's flag switched, reading the quantity on both sides of the switch. A reflective construct's `rho_A` above 1, strict (264 of 264; switch at 1 + 4e-16). A reflective construct's loading above 1 + 5e-9 in absolute value (1,027 flagged loadings; the switch lies between two adjacent doubles, the lower one being the double nearest 1 + 5e-9, so single indicators, whose loading is 1 + 2.2e-16 by rounding, are never flagged). A corrected construct correlation of 1 or more in absolute value, strict (25 of 25; switch at 1 ± 2e-16). An R² outside [0, 1], strict (43 of 43; switch at 1 ± 7e-15). A construct correlation matrix implied by the structural model with its smallest eigenvalue below 1e-8 (two switches at 1e-8 ± 4e-16): the matrix has the corrected correlations of the exogenous constructs, unit variances, and for each endogenous construct, after its antecedents, `S[j, k] = sum_i b_ij S[i, k]`; the form with disturbance variances 1 − R² flagged a different set (22 of 74 agreed). `seminr` reports this last condition only when the `rho_A`, loading and correlation checks pass, which does not change the drop decision. Together the five conditions reproduced `seminr`'s decision on 2,655 of 2,655 resamples. The kernel returns status 2 for such a resample; its eigenvalue test is a Cholesky factorisation of the matrix less 1e-8 on the diagonal, which exists exactly when the smallest eigenvalue exceeds 1e-8. R² enters only through the comparison with 0 and 1; `sum(b * Rc[pred, j])` is used, and none of five forms tried gave `seminr`'s R² bit for bit.
- **The bootstrap object** gains `boots_requested` and `boots_dropped`, after `boots` and before `seed`, in the type `nboot` was given (double or integer); `boots` counts the kept resamples. Unchanged: resample `b` is drawn after `set.seed(seed + b)` and estimated with `maxIt = 300` and `stopCriterion = 7`.

Result: on all 46 test models with reflective constructs at 100 resamples each, `aw_boot_pls()` ran natively and its bootstrap arrays, descriptive tables and counts were identical to `seminr` 2.6.0's (2,922 of the 4,600 resamples kept, the same ones), HTMT within three units in the last place, 0 of 92 kernel calls handed back to GNU R. Under 2.5.0 the engine behaves as before; the test suite runs against both versions in CI.

Clean room: only the 2.6.0 NEWS file and help pages were read; its R code was not printed or read, and the thresholds come from outputs alone.
